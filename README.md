# 岗位技能与培训采购资料

本地合成业务资料，不含真实求职者或企业信息。仓库包含往届招聘邀约、结局、当前岗位组、企业资格证据、候选人证书与时间、培训报价及采购记录。

`data/supplies.json` 按业务表保存记录，`data/fields.json` 记录各表字段及资料中出现的值类型。`historical_rounds` 描述往届批次、邀约方式和观察期限，`exposures` 与 `outcomes` 保存候选人的邀约过程和后续结果。`postings` 按共用招聘名额的岗位组组织广告；`qualifications` 记录企业确认或待核的资格组合，`changes` 保存用工变化。`candidates` 与 `certificates` 记录人选与已核资格，`quotes` 描述课程时段、席位、先修和费用，`purchases` 与 `accepted` 保存已作出的采购和接收承诺。`procurement` 记录本期预算及历史对照要求。

使用 Linux、Python 3.11 及标准库运行 `python3 -m unittest discover -s tests -v`，检查数据字段、类型、关键关联与全部分析规则。

## 采购分析包 `procurement/`

资料仓库之外，本仓库提供一套只依赖标准库的采购判断工具，回答“本轮不同购课组合有机会新增多少合格入职”，而不是给课程打平均分。

| 模块 | 职责 |
| --- | --- |
| `snapshot.py` | 决策时点不可变快照；只有 `received/at <= decision_at` 的记录可见，重跑不改动旧快照 |
| `history.py` | 往届因果证据：随机批次按最初分配做 ITT、同组替代单列、失联敏感性、优先批次仅描述覆盖、对照不足只报支持范围 |
| `eligibility.py` | 资格三分类（已满足 / 在途可满足 / 无企业证据）、证书开工有效期、先修顺序、报价截止 |
| `groups.py` | 岗位组共用名额、企业变化（缩员/改开工日/撤回补证）、接收与不可撤席位预占 |
| `courses.py` | 课程席位库存、预算、教员/考点共用冲突、可退与不可退金额 |
| `portfolio.py` | 一轮内并列比较多套购课组合，校验学员唯一、名额、席位、预算，并给未填名额打原因码 |
| `changes.py` | 企业变化后的受影响承诺、尚可转用名额、可收回金额与沉没成本 |
| `audit.py` | 采购决定回查：实可用岗位、条件性安排、预计新增收益三类依据分开并可追溯 |
| `report.py` | 命令行报告 |

### 关键口径

- **ITT 分组**：随机批次只按 `probability_initial` 的最初邀约强度（高/低邀约）入组，之后接受、递补、参加都不改变分组；同一竞争小组整体计净新增，首轮名单外的入职记为同组替代，不按人头重复算新增。
- **结局成熟度**：观察期未满的批次不进入结局比较；成熟批次内，观察期满仍失联与确证未入职分开，并对失联按“全未入职/全入职”给敏感性区间。
- **证据门槛**：每臂成熟随机小组数低于 `procurement.min_random_groups_per_arm`（本数据为 6）时，只能报告 0 到可填名额的支持范围，不用观察到的转化率做采购担保；仅优先批次没有随机对照，只描述覆盖范围。
- **资格三不混**：企业已确认且已核证书满足的为“已满足”；靠在途课程在开工前凑齐确认组合的为“在途可满足”；待确认证据、撤回证据、待核证书、过期证书、赶不上开工的课程都不得计入前两类。
- **名额与席位**：同一用工组多条广告共用一批名额；企业接收先占名额，已通知不可撤采购先占课程席位与经费；同一学员在任何方案里最多填一个岗位；为待确认去向预留的席位不能再许诺给另一家企业。
- **变更留痕**：企业缩员、改开工日或撤回补证后，原广告与原接收承诺保留可查，已接收的人不会被无声挪走；不能履约时列出受影响承诺，并分开列示尚可转用名额、可收回金额与沉没成本。
- **未填名额原因码**：`无可比往届证据`、`广告共用同一名额`（以 `shared_postings` 标记具体广告）、`学员赶不上开工`、`无合适学员`。

### 运行

```bash
# 全部测试（47 个，含资料对账与分析规则）
python3 -m unittest discover -s tests -v

# 默认决策时点 2026-12-01 的一轮采购比较
python3 -m procurement.report

# 切换到更晚决策时点，纳入 2026-12-02 送达的企业变化与新资格证据
python3 -m procurement.report --as-of 2026-12-03
```
